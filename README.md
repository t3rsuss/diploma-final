# Інтелектуальна система реверс-інжинірингу структур бінарних даних для аналізу загроз кібербезпеки

Код до магістерської роботи. Система приймає виконуваний файл PE (Windows) або ELF (Linux) і повертає
вердикт про шкідливість разом із розміткою його структури на рівні блоків по 512 байтів.

Складові системи:

- детектор шкідливості: власні LightGBM-моделі для ELF і PE x64, навчені на EMBER2024, з калібруванням
  і порогами за цільовою часткою хибних тривог; для інших типів PE використовуються готові моделі EMBER2024;
- розмітка структури: класифікатор блоків (заголовок, код, дані тільки для читання, дані, ресурси, інше),
  що працює за вмістом блока і двох сусідніх, незалежно від таблиці секцій;
- структурні правила для ELF: відсутність читаної таблиці секцій (R1, для всіх архітектур) або збіг
  розмітки з таблицею менше 0,6 (R2, лише для x86 і x86-64) піднімають вердикт «Ймовірно безпечний»
  до «Підозрілий»;
- веб-інтерфейс на Streamlit.

## Структура репозиторію

| Папка | Вміст |
|---|---|
| `src/detector` | вибір моделі, оцінка файла, рівні вердикту (`verdict.py`), структурні правила (`rules.py`) |
| `src/structure` | побудова блоків, ознаки блоків, передбачення класів (`blocks.py`, `predict.py`) |
| `src/features`, `src/parsing` | ранні ознаки на основі LIEF, патч `thrember` для розбору підписів |
| `src/models` | навчені моделі, калібратори та пороги |
| `experiments` | відтворювані скрипти навчання й оцінювання |
| `results` | результати експериментів (CSV, метрики, графіки) |
| `tests` | модульні тести |

## Встановлення

Потрібен Python 3.11.

    conda create -n diploma python=3.11
    conda activate diploma
    pip install -r requirements.txt

Бібліотека `thrember` (ознаки EMBER2024) ставиться з GitHub, у PyPI її немає, тому потрібен встановлений `git`
та доступ до інтернету.

## Запуск застосунку

    streamlit run app.py

Режим чутливості («Стандартний», «Підвищений», «Максимальний») змінює пороги лише для файлів, які оцінює
власна модель (PE x64 та ELF). Структурні правила діють лише для ELF. Файли понад 30 МБ застосунок не
аналізує, бо такі файли не входили в оцінювання.

## Відтворення експериментів

Дані, зразки файлів і згенеровані артефакти до репозиторію не входять (див. `.gitignore`).

1. Набір EMBER2024 і готові моделі:

        python experiments\download_data.py
        python experiments\vectorize_data.py
        python experiments\thrember_models.py

2. Навчання детектора (власні моделі, калібрування, пороги, метрики):

        python experiments\train_detector.py elf
        python experiments\train_detector.py win64

3. Розмітка блоків. Потрібні папки `samples\clean` (чисті PE) і `samples\elf_clean` (чисті ELF):

        python experiments\build_blocks.py
        python experiments\train_blocks.py
        python experiments\export_block_model.py

4. Оцінювання на чистих файлах і шкідливих зразках. Шкідливі зразки оцінюються в ізольованій віртуальній
   машині через `experiments\vm_score.py` та `experiments\struct_extract.py`; пакет для неї
   збирає `experiments\make_vm_pack.py`.

        python experiments\eval_own_clean.py
        python experiments\eval_malware.py
        python experiments\threshold_table.py
        python experiments\plot_roc.py
        python experiments\compare_models.py

5. Аналіз пропущених зразків і структурних ознак:

        python experiments\inspect_missed.py
        python experiments\struct_eval.py
        python experiments\rules_eval.py
        python experiments\extra_eval.py

   Скрипт `rules_eval.py` рахує R2 без обмеження за архітектурою і призначений для довідкового аналізу ознак
   PE; остаточні числа для ELF дає лише `final_elf_eval.py`.

6. Чисті ELF інших архітектур і підсумкове оцінювання ELF:

        python experiments\fetch_clean_multiarch.py <папка>   (потрібен Linux з dpkg-deb)
        python experiments\arch_stats.py <папка із зразками> results\mal_elf_arch.csv

   Файли `results\multi_<арх>_scores.csv` і `results\multi_<арх>_struct.csv` створюються так само, як у кроці 4
   (`vm_score.py`, `struct_extract.py`), окремо для кожної архітектури.

        python experiments\check_duplicates.py
        python experiments\final_elf_eval.py

## Тести

    python -m pytest tests -q

## Обережно зі зразками

Шкідливі файли в репозиторії відсутні. Завантажувати їх у застосунок слід лише з ізольованого середовища,
не запускати та не відкривати подвійним клацанням. Антивірус може блокувати доступ до тимчасових файлів, які
Streamlit створює під час завантаження.

## Обмеження

- Власна модель є лише для ELF та PE x64. Файли Win32 та .NET оцінюють готові моделі EMBER2024 з фіксованими порогами.
  На тестовій вибірці EMBER2024 власна модель ELF поступається готовій (AUC 0,9854 проти 0,9929).
- Структурні правила та порогові значення режимів підібрані на тих самих зразках, на яких їх оцінено;
  відкладеної вибірки немає. Частина чистих x86-64 файлів (80 %) входила до навчання розмітки блоків,
  тому незалежне підтвердження для R2 дають 24 додаткові файли x86-64 і 192 файли i386.
- Чисті набори однорідні: системні файли однієї версії Windows, збірки Ubuntu і пакети Debian з каталогів
  `/bin` та `/sbin`. Частка хибних тривог на них не переноситься на довільне програмне забезпечення.
- Шкідливих ELF лише 64 (із них 19 x86-64, по одному-двоє для AArch64, PowerPC, m68k і SuperH), тому
  довірчі інтервали широкі, а оцінки за окремими архітектурами орієнтовні.
- Для ELF вибірка калібрування невелика, тож поріг «шкідливий» на тестових даних дає більшу частку хибних
  тривог, ніж цільова (див. `results\detector_elf_metrics.json`).
